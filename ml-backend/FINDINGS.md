# Repository inspection (before integration)

- `NLP_Linear_SVM_Complaint_Classification.ipynb` and `FINALDATA.xlsx` exist at repository root. The notebook uploads a differently named file in Colab, but its two pipelines are word (1,2) + character (3,5) TF-IDF (50,000 each, sublinear TF) and balanced LinearSVC (C=1, seed=42, 10,000 iterations). It uses an 80/20 category-stratified split.
- This is a Next.js 16 App Router/React 19 application, with Next route handlers and Supabase SSR/browser clients, not a standalone Flask server. Existing `/api/classify` runs a JS Naive Bayes classifier (`lib/classifier`) using an embedded dataset; resident form calls it twice (preview and submission). Staff-assisted filing calls that classifier locally. Existing backend APIs include `/api/kiosk/submit`, which calls the idempotent `kiosk_submit_complaint` Supabase RPC.
- `complaints.predicted_category` and `predicted_case_type`, and their confirmed counterparts, are `case_category` enums (`Criminal`, `Civil`, `Administrative`) and cannot store the notebook's specific labels. `classification_status`, `prediction_model`, and `complaint_reviews` already exist; the specific label requires an additive text column. No new broad or final enum columns are needed. Existing `prediction_confidence` must not be filled from raw SVM scores.
- Resident submissions use `createComplaint` -> `create_complaint` RPC via authenticated browser Supabase, then evidence and receipt. The kiosk uses a browser IndexedDB AES-GCM offline queue (not SQLite in this repository), service worker and sync scheduler. The kiosk sends a stable client submission UUID; its RPC deduplicates retries. Current kiosk classification is computed on the client, including offline. New ML must instead be invoked on the server during online replay, before the existing RPC; unavailable ML must not block filing.
- Captain/OIC are allowed to confirm categories by the existing `complaints_categorization_guard`; secretary is not. `confirmOfficialCategorization` writes confirmed enum fields and `complaint_reviews`, leaving predictions intact. Lupon reads confirmed categories. Existing category display, filters and reports use enum values and must continue to work.
- Existing status and notification transitions live in Supabase SQL/RPCs and should not be replaced. `supabase/manual/` contains manually applied migrations; deployment requires applying new SQL before storing specific labels. No live schema access is assumed from the local inventory.
